## 二、两个事件

### 事件 1｜Day 26 发布：我以为"线上就是最新代码"

**当时怎么想**：Day 25 跑完 20 项发布前检查，接口全绿、页面全开，我认为可以发布 v1.0 了。发布这件事在我脑子里就是"把文件传上去"。

**发现了什么**：发布前要做的一件事是给版本打 tag，tag 得指向一个提交。我去核对"线上现在对应哪个提交"，核不出来。

结论是：**v1.0 之前的线上，是按文件从不同历史版本拼出来的叠加态**，没有任何一个提交号能代表它。证据在 `docs/release-v1.0.md §0`：

| 线上文件 | 对应 git 版本 |
|---|---|
| `data/mock-sessions.json`、`js/pages/status.js`、`js/pages/topics.js`、`pages/status.html`、`pages/topics.html` | `77eefb5`（10-07） |
| `js/api.js`、`js/components/item-card.js`、`pages/records.html` | `34fd16f`（10-09） |
| `data/topics.json` | `817aa73`（10-02） |
| `js/components/interact.js`、`js/components/topic-card.js` | `afb499e`（09-29） |
| `js/storage.js` | `e4c9259`（10-07） |
| `pages/result.html` | `8d63027`（10-07） |
| `js/speech.js`、`pages/dialogue.html`、`styles/main.css`、`index.html` | **不在 git 里**（从未提交） |

四个不同时期的版本，加四个从来没进过 git 的文件，混在同一份线上。

**改了做法**：
1. v1.0 那次发布，先取了发布前快照（`.deploy/snapshots/before-v1.0/`，23 个文件）再上传 —— 因为"回退"这件事在静态托管上只能靠重传旧文件（官方 help 原文 `no version management`）
2. 验证部署**不用 curl 看 200**，用托管侧 ETag 与本地 `md5sum` 逐文件比。curl 拿到 200 也可能是拦截页
3. 今天（Day 28）做同样的事：线上 7 个文件与本地 HEAD 比 md5，**7/7 一致**，才敢说"线上跑的是 `e8ed427`"

### 事件 2｜Day 28 验收：我以为"有备份就等于有退路"

**当时怎么想**：`.deploy/backups/db/` 里三张表的导出文件都在，09:16 导的，行数 7/20/8，我一直在文档里把它当"数据备份"写。

**发现了什么**：今天为了把备份补到最新，先把旧文件打开看了一眼 —— **7 行全是演示数据**（`S-MOCK-01`~`S-MOCK-05`、`S-DAY21-VERIFY`、`S-TEST-DAY20`），一条真实练习记录都没有。

原因是时间差：备份 09:16 导，清空演示数据 12:55，我第一次真机练习 14:28。这份文件保的是**已经被推翻的那个状态**。

**这件事比"没有备份"更危险**：没有备份，我知道自己没退路，会小心；有一份内容作废的备份，我会以为有退路，真出事时把它灌回去，结果是演示数据全回来了、真实数据一条没救回来。

**改了做法**：
1. 备份要**验内容**，不只验存在：行数对不对、里面装的是不是当前状态
2. 重导时旧的先改名保留（`*.json.bak-0916`），新的覆盖主文件 —— 两份都在，将来能对照"曾经存的是什么"
3. 备份必须带"这是哪一刻"的语义。`20261017` 这个日期不够，因为同一天里状态会变两次

## 三、这条认知改变了什么做法

三条可迁移的规则，都不依赖记性，靠命令能重跑：

| 规则 | 具体动作 | 判据 |
|---|---|---|
| **1. 交付前先证明"你看到的就是你在说的那个"** | 线上文件与本地的 md5 逐文件比；比 tag 与 HEAD 用 `git rev-parse v1.0^{}`（`git rev-parse v1.0` 给的是标签对象，不是提交） | 7/7 一致才算；差一个文件就不能说"线上是新版" |
| **2. 备份要验内容，不只验存在** | 打开文件数行数、看里面的 sessionId 是哪几场 | 出现不该存在的记录 = 备份已作废 |
| **3. 把关键动作写成流程硬步骤** | "发布前取快照"写进 `docs/release-v1.0.md §3` 第 1 步，不靠临时想起来 | 没取快照就不许上传 |

★ 还有一条今天补的：**改配置类文档前，先把线上实际值查一遍**。
今天查到 `tcb routes list` 这一列是"路径透传"还是"鉴权"，取决于解析时取第几格 ——
取错一格会把"已开"读成"未开"，结论正好相反。这类判断不能靠印象。
